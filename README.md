- 구현: AI가 SQL·ORM 변경에서 검수할 SQL과 맥락을 정리하고, Remote MCP의 Go 코어가 게시 SSOT로 판정하도록 분리했습니다. 개발자가 같은 대화에서 업무 의미를 답하면 새 검수 ID로 재검수하며, DDL은 코딩 가이드로, DML은 티켓 미리보기·명시 동의로 연결합니다. PR에서는 고정 스냅샷으로 DB 변경을 선체크하고 SQL 도출·SSOT 검수·1차 개발자/2차 DBA 보고서를 연결합니다.
- 결과·상태: Helm·Terraform·GitHub Actions로 배포 인프라를 구성하고 ORM 9종 대상 E2E 검증을 마쳤습니다. 현재 시범 운영을 준비하고 있으며, 운영 효과는 시범 운영 이후 측정할 범위입니다.

#### AI 기반 DB 변경 검수 자동화(DBQ) · 2026.08–현재 · 시범 운영 준비

- DB 변경 요청이 DBA와 여러 차례 왕복하는 문제를 줄이기 위해 검수 자동화 도구를 단독 설계·개발했습니다. 판정 코어부터 AI 인터뷰, 기준정보(SSOT), DBA 검토함, Remote MCP, 플러그인과 배포 인프라를 담당했습니다.
- Go 결정적 코어가 표준과 위험 항목을 판정하고, AI는 코드·SQL 해석과 필요한 업무 질문을 맡도록 경계를 나눴습니다. AI의 설명·답변 수집을 엔진 PASS나 DBA 승인으로 취급하지 않게 했습니다.
- Claude Code·Codex에서 명시적으로 요청한 SQL·ORM 변경을 Remote MCP의 게시 SSOT로 검수하도록 연결했습니다. PASS여도 개발자 확인 사항이 남으면 같은 대화에서 답변받고 새 review_id와 이전 검수 연결로 재검수합니다.
- DDL 검수 결과는 ORM·마이그레이션 구현에 사용할 코딩 가이드로, DML은 최신 검수의 티켓 미리보기와 명시적 생성 동의로 이어지도록 구성했습니다. 로컬 검수·티켓 생성·DBA 승인·SQL 실행의 상태를 분리했습니다.
- PR 변경은 고정 스냅샷의 DB 변경 선체크 → SQL 도출 → 원격 SSOT 검수로 연결하고, 개발자용 1차와 DBA용 2차 보고서를 구분했습니다. 동적 SQL과 누락 설정을 DB 변경 없음으로 처리하지 않고, 업무 답변과 소스 보완을 분리했습니다.
- 롤백 SQL 생성과 요청 맥락·검수 이력 관리를 구현하고 Helm·Terraform·GitHub Actions로 배포 인프라를 구성했습니다. ORM 9종 대상 E2E 검증을 수행했으며, 현재 시범 운영 준비 단계로 운영 리드타임·도입 효과는 아직 기재하지 않습니다.

## 로컬 실행 및 검증

Python 3와 정적 파일만으로 빌드됩니다.

```bash
python3 scripts/build.py
python3 -m unittest discover -s tests -v
python3 -m http.server 8765
```

브라우저에서 `http://localhost:8765/`를 열고, 이력서는 `resume.html`에서 인쇄/PDF 저장할 수 있습니다.

`profile.json`이 경력 내용의 기준입니다. `scripts/build.py`는 `index.html`, `resume.html`, `README.md`를 생성합니다. CSS와 데모는 소스 자산으로 보존합니다.

`node scripts/test_demo_state.cjs`는 판단 규칙을 검사합니다. Playwright가 설치된 환경에서는 `BASE_URL=http://localhost:8765 node scripts/test_demo.cjs`로 네 가지 데모·모바일·키보드 동작을 검사할 수 있습니다.

- 회사 업무의 상태는 프로젝트별로 구분합니다. 검수/파일럿을 운영 완료로 바꾸지 않습니다.

- 로컬 빌드와 검증은 배포를 수행하지 않습니다.
